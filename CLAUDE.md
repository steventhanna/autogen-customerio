# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Auto-generated Rust client for the [Customer.io APIs](https://docs.customer.io/api/). Customer.io
ships one OpenAPI 3.1 spec per API (`https://docs.customer.io/files/{journeys-track,journeys-app,pipelines}.json`);
each is vendored into its own module under `src/<service>/` (generated by openapi-generator). Only
`src/lib.rs`, `src/client.rs`, and `src/ids.rs` are hand-written. Structure mirrors the sibling
`autogen-stedi` and `autogen-dosespot` repos.

## Architecture

- Each spec → one module (`track`, `app`, `pipelines`) containing its own generated `apis/` and
  `models/`, and one Cargo feature. `app` also enables `tokio`, `tokio-util`, and `reqwest/stream`
  (Assets file uploads stream from disk).
- The rust generator emits absolute `crate::apis` / `crate::models` paths. `generate.sh` rewrites
  these to `crate::<service>::…` after copying the generated code into `src/<service>/`, so it
  compiles inside a submodule. **Preserve the rewrite's ordering.**
- `src/client.rs`: `CustomerIoClient` holds a `Region` (US/EU) and a
  `reqwest_middleware::ClientWithMiddleware` (`CustomerIoClient::builder(region).with(mw).build()`).
  The three APIs use three credentials, so each accessor takes its own credential newtype and
  returns that API's `Configuration` with the region's base URL: `track(&TrackSiteId, &TrackApiKey)`
  (Basic), `app(&AppApiKey)` (Bearer), `pipelines(&PipelinesApiKey)` (Basic, empty password).
  Credential types redact `Debug`. The region host table is hand-written; `tests/auth.rs` checks
  the US hosts against the specs' servers.
- `src/ids.rs`: strict ID newtypes (`BroadcastId`, `CampaignId`, `DeliveryId`, …; i64 or String,
  private inner field). `scripts/fix-id-types.py` rewrites an allowlist of generated parameters,
  fields, and entity-model `id` fields to them. Unknown names stay raw. Keep the script's tables
  and `src/ids.rs` in sync. Guarded by `tests/ids.rs`.
- The crate never creates spans or logs URLs (guarded by `tests/middleware.rs`).

## Commands

```bash
cargo check --all-features                                   # build / type check
cargo test --all-features                                    # run tests
cargo check --no-default-features --features "app,native-tls"  # validate one feature gate
./generate.sh                                                # regenerate from latest specs
cargo doc --no-deps                                          # generate docs
```

Do not run `cargo fmt` over the crate: it reformats generated code and breaks the idempotent
regeneration. Format hand-written files with `rustfmt --edition 2024 src/lib.rs src/client.rs src/ids.rs tests/*.rs`.

## Regeneration

`./generate.sh` fetches the three specs, records their combined SHA-256 in `SPEC_HASH` (always of
the raw upstream documents), patches the specs, generates each into a temp dir, vendors `apis/` +
`models/`, rewrites crate paths, applies post-generation fixes, and runs `cargo check` (all
features, then each API alone). The run is idempotent. Do not hand-edit anything under
`src/<service>/` — fix it in a script instead.

The Customer.io specs need a lot of patching. Each script names the defect it fixes and **exits
non-zero on any shape it does not recognize**, so upstream drift fails the daily job instead of
silently producing wrong types. Spec patches, in order:

1. `drop-webhook-schemas.py` — removes the inbound reporting-webhook payload schemas and the
   `webhooks` section (no operation uses them; their tags are inconsistent upstream).
2. `fix-default-security.py` — App defaults to `Bearer-Auth`; Assets/Design Studio operations
   declare no security and would otherwise send no `Authorization` header.
3. `rereference-schemas.py` — the specs are fully dereferenced; inline copies of component
   schemas are replaced by `$ref`, so each component is one Rust type.
4. `fix-schema-titles.py` — punctuation in titles ("SMS / MMS") makes the model file and its
   `pub mod` line disagree.
5. `fix-duplicate-parameters.py`, `fix-duplicate-enum-values.py` — spec duplicates.
6. `fix-discriminator-mapping.py` — derives `mapping` from each member's one-value tag enum,
   hoists inline members, strips the tag field from leaves (else serde writes it twice and
   cannot deserialize), and turns discriminated `anyOf` into `oneOf`. Guarded by `tests/tagged_unions.rs`.
7. `fix-inline-oneof.py` — 3.1 inline scalar `oneOf` members crash the generator (NPE on
   `getType()`); nullable scalars become `type: [T, "null"]`, scalar unions get titles.
8. `fix-integer-format.py` — all integers become `int64` (the generator hard-codes `i32` for
   format-less integers; timestamps overflow in 2038).

Post-generation: `fix-duplicate-fields.py`, `fix-datetime-query-params.py` (currently a no-op),
`fix-id-types.py`, `fix-open-enums.py` (`UnknownValue(String)` fallback; guarded by `tests/open_enums.rs`).

The generator version is **pinned** via `GENERATOR_VERSION` in `generate.sh`; the JAR comes from
Maven Central (cached under `~/.cache/openapi-generator`), so local and CI output match with only a
JDK installed. Bumping it is deliberate: regenerate and review the diff. `supportMiddleware=true`
is what makes `Configuration.client` a `ClientWithMiddleware`; do not remove it.

CI: `update-spec.yml` runs `generate.sh` daily; on a spec-hash change it bumps the patch version
and opens an `update/customerio-spec-*` PR. Merging that PR triggers `tag-release.yml`, which tags
the release and publishes to crates.io (needs a `CARGO_REGISTRY_TOKEN` secret). Publish runs as a
second job in the same workflow because a tag pushed with the default `GITHUB_TOKEN` does not
trigger a separate `on: push: tags` workflow.
